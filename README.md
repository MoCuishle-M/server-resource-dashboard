# 算力资源台 · Server Resource Dashboard

面向服务器管理员、10个使用组及灵枢平台的资源看板。访客免登录查看；组接口人认证后申请；管理员维护资源并审批。真实数据库初始不包含示例服务器。

## 功能

- **不可用与隐藏**：资源状态增加“不可用”，阻止新申请和审批；若还有有效预约，先取消或释放后再设为不可用。管理员可独立设置“隐藏 · 仅管理员可见”，支持单台编辑、批量修改、Excel/CSV导入、状态/隐藏筛选和导出。接口人、未认证账号及访客的服务端响应均不包含隐藏服务器及相关申请、历史；混合申请中的可见服务器仍保留占用显示。管理员可随时恢复公开显示。
- **网页字号**：提供100%、115%、130%、150%四档，默认130%，资源列表、弹窗与菜单统一缩放；浏览器记住个人选择，不改变他人的显示偏好。
- **公告与签名**：公告栏和作者签名对所有访客公开；管理员在“网站设置”编辑，保存至数据库，支持多行纯文本并记录变更历史。
- **管理员管理**：现有管理员可在“网站设置”填写新管理员登录邮箱。已有认证账号立即授权；其他账号使用受邀邮箱登录后绑定稳定Site用户ID，无需工号认证。邀请不发送邮件，管理员可取消邀请或撤销其他管理员权限；不能撤销自己或最后一位管理员。邀请、邮箱与账号资料只对管理员可见。
- **独占 / 共享**：管理员在服务器上配置占用模式。共享服务器允许不同组同时预约，不划分卡数，列表合并显示当前使用组；独占服务器保留冲突校验和高优抢占。已有资源默认独占，存在重叠共享预约时不能切回独占。同组同机重复预约按一台统计，累计小时按时间并集计算。
- **灵枢平台状态**：使用方式为灵枢平台的资源支持“通过灵枢平台使用”“通过工单占用”“通过统一资源池+灵枢平台使用”，旧资源默认第一项。可单台编辑、批量修改、按状态筛选，以及Excel/CSV导入导出；导入可填写“灵枢平台状态”列，也兼容在“状态”列填写这三项。资源可申请/维护中状态与预约占用逻辑继续保留。改为裸机会清除平台状态。
- **资源管理**：服务器名称、类型、IPv4/IPv6、裸机/灵枢平台、位置、备注、维护状态；搜索、筛选、新增、编辑、删除、批量删除。
- **批量IP搜索**：在服务器资源或使用排期搜索框输入或粘贴多个IP，用空格、英文逗号、换行（可混用）分隔，按IP精确匹配并合并结果，支持IPv4/IPv6。排期可叠加服务器类型多选、团队和日期范围；资源列表可叠加类型、使用方式、状态筛选。名称、类型、位置、备注和不完整IP继续使用文本模糊搜索。
- **类型多选**：类型筛选使用复选框下拉面板，可搜索、全选、清空，点击“确定”应用，“取消”、点击外部或Esc放弃本次修改。多个类型取并集，并与IP、使用方式、状态筛选叠加；清空后确认显示空结果，全选后确认恢复全部类型。
- **批量修改**：选中资源后，勾选需要修改的字段。支持名称模板（`{name}`、`{ip}`、`{index}`）、类型、使用方式、占用模式、位置、备注和状态，IP保持不变。位置和备注可勾选后留空清除。整批校验，任一失败不会部分写入，逐台记录变更前后。
- **表格导入**：直接上传Excel `.xlsx`（支持选择可见工作表、下载Excel模板），也支持复制粘贴（TSV）或UTF-8 CSV上传；下载模板、导入预览、整批校验、重复IP/名称拦截；“占用模式”列可选（独占/共享，默认独占）；每批最多200行、文件最多5MB。可选择新增资源或按IP更新已有资源，更新模式下只需IP和要修改的列，空白保留原值；未匹配或重复IP会阻止整批更新。Excel公式请先转为纯值，旧版`.xls`需另存为`.xlsx`。支持CSV导出。
- **10个组与灵枢平台**：默认01组至10组，另提供“灵枢平台”作为独立使用者，可单独申请、审批和展示排期，配置接口人并统计用量。普通组接口人仍只能代表本组申请；管理员可代表任一使用者安排排期。灵枢平台名称固定，真实接口人姓名和工号留空。
- **使用排期**：默认显示北京时间周一00:00至下周一00:00的整周连续时间轴；支持切换单日（完整24小时）、自定义起止日期时间、前后周/日、服务器搜索与团队筛选。预约按真实时长绘制，跨日保持连续，在查看范围边界裁剪，共享重叠任务分行展示；保留已提前释放的实际使用历史。可从服务器行发起申请，预填当前查看范围内最多3小时。
- **申请时间**：保留北京时间09:00–12:00、12:00–14:00、14:00–17:30、17:30–21:00、21:00–次日09:00预设时段；也支持自定义起止时间及跨日预约。
- **申请审批**：多服务器申请、用途、普通/高优/紧急优先级；批准、拒绝、取消、提前释放。待审批申请不占用资源。
- **取消部分时段**：已批准申请可自定义释放未来的部分时间，支持只调整选中的服务器，确认前预览取消与保留时段。例如9–19点取消12–14点后，保留9–12点、14–19点，独占模式继续生效；空出的12–14点可重新申请。接口人操作本组，管理员操作任意组；必须填写原因并记录历史，保留已发生的使用统计。可从申请列表、申请详情或服务器当前预约进入。
- **高优抢占**：只允许抢占更低优先级任务，管理员必须勾选确认并填写原因。原预约保留，冲突前后未被抢占的时段继续有效。
- **历史追踪**：每台服务器当前/未来/过去使用情况、原使用组、审批原因、抢占记录与资源变更；管理员可查看变更前后字段。
- **历史筛选**：变更历史可多选操作类型，并与关键词、执行起止时间共同筛选。时间使用北京时间，可只填写起点或终点，结束时间包含所选的整分钟或整秒；支持重置，导出仅包含筛选结果，记录时间展示完整年月日和时分秒。
- **独立演示**：`/demo` 使用浏览器内存中的示例资源，可切换演示角色；不读取或写入生产记录，刷新即重置。

## 身份与权限

| 角色 | 查看 | 提交申请 | 处理本组申请 | 资源维护/审批/组管理 |
| --- | --- | --- | --- | --- |
| 访客 | 是 | 否 | 否 | 否 |
| 已登录、未认证 | 是 | 否（可申请接口人认证） | 否 | 否 |
| 已认证组接口人 | 是 | 本组 | 是 | 否 |
| 服务器管理员 | 是 | 可选择组别 | 全部 | 是 |

Sites原生ChatGPT登录负责身份验证。工号和姓名用于业务身份认证，不作为密码。服务端以稳定的Site用户ID判断权限；浏览器中不提供真实角色切换。组信息维护不会直接授予登录账号权限，管理员须单独审核接口人认证。

首位管理员邮箱通过Sites服务器端秘密变量 `ADMIN_EMAILS` 配置，不写入源码。第一次匹配的ChatGPT登录将注册稳定的管理员账号身份，后续按用户ID授权。公开访客无法抢注管理员。增加初始管理员时可配置逗号分隔的多个邮箱。移除初始化邮箱不等于撤销已注册管理员身份。

## 使用流程

1. 管理员登录，在“团队与接口人”配置10个组的名称、工号和接口人姓名。
2. 在“服务器资源”添加或批量导入服务器。
3. 接口人使用各自的ChatGPT账号登录，点击左下角账号，填写组别、工号、姓名并申请认证。
4. 管理员在“团队与接口人”的身份审核表中核验并批准。
5. 接口人选择服务器、时间段、用途和优先级，提交申请。
6. 管理员审批。若抢占低优任务，确认具体冲突并填写原因。
7. 所有人可在总览、排期、团队统计及历史中查看资源使用情况。

## 本地运行

Node.js >=22.13、npm、Git。

```bash
npm ci
npm run db:generate  # 已提交迁移时无需重复生成
npm run build
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_rainy_serpent_society.sql
npm run dev -- --port 5173
```

本地打开开发服务器打印的网址。只在首次创建本地数据库时应用初始迁移，后续按顺序应用未执行的新迁移。开发数据保存在被Git忽略的 `.wrangler/state/`，与线上D1隔离。

Portable开发预览保留Sites starter的loopback模拟登录：`/signin-with-chatgpt?return_to=/` 登录为 `seedy@sites.test`，开发配置仅在 `serve` 时将该身份视为本地管理员。生产构建不包含模拟登录，生产管理员邮箱由Sites环境变量提供。

## 数据一致性

数据库分为资源、组、账号、申请、占用、审计和版本控制表。每个实体独立保存类型化JSON。审批、占用分段、操作记录及版本递增在一个D1事务批次中提交。数据库CHECK约束校验旧版本，确保并发审批或编辑时只有一个基于同一版本的操作可以提交，其余完整回滚并提示刷新。

时间以UTC ISO字符串存储，界面统一按Asia/Shanghai显示。占用采用左闭右开区间 `[开始, 结束)`；相邻时段不冲突。累计使用统计有效的已批准/已提前释放时段，排除未使用的未来时段、已取消预约和被抢占的原始区间。

删除资源为软删除，历史不随之删除；仍有未来或当前预约的资源不能删除或转维护。撤销接口人权限不取消其已有批准预约。写接口校验登录身份、角色、组归属、请求来源和数据版本。公共接口隐藏其他人的认证邮箱、账号标识和原始审计快照。

## 部署

`.openai/hosting.json` 绑定Sites项目及D1数据库 `DB`。保留starter的 `sites()` 构建集成，通过Sites source workflow同步源码、构建打包、保存版本并部署；Sites负责应用线上迁移。`ADMIN_EMAILS` 在Sites中作为秘密变量配置。公开访问由Sites访问策略设置为public；应用内写权限仍由服务端控制。

源码保存在GitHub私有仓库；GitHub源码权限与网站公开访问是独立设置。

## 当前边界

本项目登记和协调服务器使用，不连接SSH、不执行远程命令，也不自动采集CPU/NPU负载。“当前使用”指已批准的预约占用。若后续需要真实设备利用率，可增加独立采集端，经授权HTTPS接口上报。
