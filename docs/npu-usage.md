# NPU 使用分析

## 页面怎么用

1. 访客无需登录即可打开左侧“NPU 使用分析”，管理员和已审批的接口人也可查看。访客和接口人的排行、趋势和汇总仅按可见服务器计算，不包含隐藏服务器。普通成员仍无法查看。
2. 选择北京时间开始、结束日期，最多 7 个自然日；今天只统计到当前时刻。
3. 选择卡占用率或计算利用率，以及升序或降序。点击机器名查看双折线和最新卡状态，点击组名查看组内汇总或指定机器。
4. 点击“刷新数据”读取最新上报。此页不会定时刷新遥测数据。

单日曲线每点 15 分钟，跨日每点 60 分钟。勾选框控制两条曲线，鼠标或左右方向键查看数据点。最新卡状态不随历史日期回溯；没有快照时仍显示历史统计。

| 指标 | 含义 |
| --- | --- |
| 卡占用率 | 占用卡分钟 / 有效观测卡分钟。是否占用由采集端判定。 |
| 计算利用率 | 有效计算指标的百分比之和 / 对应的卡分钟。 |
| 覆盖率 | 有效观测卡分钟 / 预期卡分钟；选计算指标时使用有效计算指标卡分钟。低于 80% 展示数据但不列名次。 |
| 组排行 | 只统计有效排期内的观测；同组同机重复排期去重，高优抢占和升级等不可用时段排除。 |

共用时段的整机观测分别计入每个参与组，不能理解为各组进程的独立利用率；集群汇总只计一次。集群统计只包含已接入机器。缺测显示“—”，不等于利用率为 0。只有分钟数据而无快照时，缺数据日期的预期卡数按所选范围中该机已上报的最大卡数计算。

## 真实数据怎么接入

本仓库提供展示、接收接口和存储，不包含服务器采集脚本。采集端需要自行采集 NPU 状态、统一占用判定，并处理定时上报与失败重传。

1. 部署包含 `0003_npu_telemetry.sql` 的版本，Sites 会应用新增表迁移。本地预览需单独应用未执行的迁移。
2. 在 Sites 服务端配置至少 32 字符的秘密变量 `NPU_INGEST_TOKEN`，并把相同密钥安全配置到采集端。密钥不能写进源码或网页。
3. 在台账中登记唯一匹配的 IP，区域必须明确为蓝区，资源不能已删除。
4. 采集端向站点的 `POST /api/npu-usage/ingest` 发送 JSON，请求头包含 `Content-Type: application/json` 和 `Authorization: Bearer <密钥>`。
5. 从真实服务器验证能通过 Sites 访问校验并成功上报，再检查页面的机器、时间和指标。应用密钥认证与 Sites 网关访问是两层校验。

### 请求示例

以下 IP 是示例地址，实际替换为台账 IP。时间为北京时间 2026-11-12 09:00。

```json
{
  "day": "2026-11-12",
  "ip": "192.0.2.1",
  "expected": 2,
  "points": [[540, 2, 1, 2, 60]],
  "snapshot": {
    "at": 1794445200000,
    "cards": [
      {"key": "0-0", "state": "active", "util": 60, "hbm": 50},
      {"key": "1-0", "state": "idle", "util": 0, "hbm": 0}
    ]
  }
}
```

- `day` 是北京时间日期，`expected` 是预期卡数（1–128）。
- `points` 每项依次是 `[当天分钟索引, 有效观测卡数, 占用卡数, 有计算指标的卡数, 计算利用率百分比之和]`。540 是 09:00；示例占用率为 50%，计算利用率为 30%。同一请求中每分钟最多一条，不能上报未来分钟。
- `snapshot` 可省略。`at` 是 Unix 毫秒时间戳，必须属于 `day` 且不在未来；`cards` 卡标识不能重复，数量不能超过 `expected`。
- `key` 使用数字-数字形式；`util`、`hbm` 是 0–100 的百分比或 `null`。
- `state` 支持 `idle`、`active`、`occupied_low`、`occupied_unknown`、`fault`、`smi_fail`、`missing`、`no_data`。
- 一次只传一台机器一天的数据，最多 1440 条分钟记录，请求上限 100,000 字节。同一分钟重传覆盖原值、不重复累加；旧快照不会覆盖更新的快照。

服务端未配置有效密钥返回 503；认证失败返回 401；IP 不唯一、已删除或不是蓝区返回 409。
